## Web research findings

Items with "(snippet)" come from search-result summaries only.

### Upload reply

- [web] The first call returns 202 with a `Location` header (status URL) and a `Retry-After` header (sample: 5 s). Request checks occur before the 202; an invalid request gets 400 at once. https://learn.microsoft.com/azure/architecture/patterns/async-request-reply
- [web] Product variants: 202 with an `Operation-Location` header and no id in the body; 200 with `{"JobId": ...}`; `{"job_id": ...}`. https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/prebuilt/batch-analysis , https://docs.aws.amazon.com/textract/latest/dg/API_StartDocumentTextDetection.html , https://docs.reducto.ai/workflows/async-overview.md
- [web] The status endpoint returns HTTP 200 for each job state, also for failed; the state is in the body. https://learn.microsoft.com/azure/architecture/patterns/async-request-reply

### Status vocabulary

- [web] Vocabularies: `pending/processing/completed/failed`; `queued/running/succeeded/failed`; `notStarted/running/succeeded/failed` (plus `skipped` per document); `IN_PROGRESS/SUCCEEDED/FAILED/PARTIAL_SUCCESS`. https://docs.landing.ai/api-reference/parse/ade-get-parse-jobs.md , https://docs.kinetk.ai/api-reference/api-reference/intelligence-jobs-status , https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/prebuilt/batch-analysis , https://docs.aws.amazon.com/textract/latest/dg/API_GetDocumentTextDetection.html
- [web] Products show the current step as a number (`progress`, `percentCompleted`), not as a named step. No product in the sample has a named step such as "parsing". https://docs.landing.ai/api-reference/parse/ade-get-parse-jobs.md
- [web] Fields appear by state: `result` only when completed, `error` (`code`, `message`) only when failed. https://docs.landing.ai/api-reference/parse/ade-get-parse-jobs.md

### Partial success

- [web] Three patterns: a top-level `PARTIAL_SUCCESS` status with a `Warnings` list; status stays `completed` and failures are in result metadata; a per-page `success` flag. https://docs.aws.amazon.com/textract/latest/dg/API_GetDocumentTextDetection.html , https://docs.landing.ai/api-reference/parse/ade-get-parse-jobs.md , https://developers.llamaindex.ai/llamaparse/parse/guides/retrieving-results/index.md
- [web] Design-guide rule: partial failures go in the operation metadata; a failed run ends with an `error` field. https://google.aip.dev/151
- [web] No source describes "main result ready, summary step failed". The patterns above are the nearest.

### Multi-file uploads

- [web] Batch status is separate from item status: one batch id, counts of succeeded and failed items, one entry per document with its own status and error. Item failures do not change the batch status. https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/prebuilt/batch-analysis
- [web] One invalid file in a multi-file upload: one product accepts the valid files and returns 207 with one entry per failed file. HTTP has no standard for a partial upload (snippet). https://docs.camunda.io/docs/apis-tools/camunda-api-rest/specifications/create-documents/

### Input rejection

- [web] 415 = format not supported; 413 = content too large; 422 = syntax valid but the instructions cannot be processed. https://www.rfc-editor.org/rfc/rfc9110.html
- [web] Products differ: one uses 400 for all of unsupported format, too large and unreadable; one returns 413 for a file that is too large. https://docs.aws.amazon.com/textract/latest/dg/API_StartDocumentTextDetection.html , https://developers.llamaindex.ai/python/cloud/general/troubleshooting/
- [web] FastAPI returns 422 by default for each request validation error, also for a missing field, with body `{"detail":[...]}`. https://fastapi.tiangolo.com/tutorial/handling-errors/

### Password-protected and scanned PDFs

- [web] A password-protected PDF is a job failure with its own non-retryable code, found during processing and not at upload: `PDF_IS_PROTECTED`, `PASSWORD_PROTECTED_FILE`. A corrupt file has its own code (`PDF_IS_BROKEN`). https://developers.llamaindex.ai/python/cloud/general/troubleshooting/ , https://docs.extend.ai/password-protected-files
- [web] A PDF with no extractable content: one product fails the job with `NO_DATA_FOUND_IN_FILE`. Text-extraction libraries return an empty string for scanned pages and raise no error; one PDF can mix text pages and scanned pages (snippet). https://developers.llamaindex.ai/python/cloud/general/troubleshooting/ , https://apryse.com/blog/pdf-text-extraction-ocr-ai

### Result expiry and unknown id

- [web] Expired results: two products return 410 and keep 404 for unknown ids; two others return 404 for both. https://docs.kinetk.ai/api-reference/api-reference/intelligence-jobs-status , https://docs.reducto.ai/workflows/deletion.md , https://developers.llamaindex.ai/llamaparse/general/data_retention/index.md
- [web] Expiry time: some products put a timestamp in the body (`expires_at`); others state it only in the docs. https://platform.claude.com/docs/en/api/messages/batches/retrieve.md
- [web] Unknown id: mostly 404 with a structured body. https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/v3-error-guide

### Health

- [web] A critical dependency down gives 503 (snippet). A draft format uses `status` = `pass` / `warn` / `fail`. https://www.ietf.org/archive/id/draft-inadarei-api-health-check-06.html

### Pitfalls a tester notices

- [web] Page numbers start at 1 in one product and at 0 in another. https://docs.landing.ai/api-reference/parse/ade-get-parse-jobs.md , https://docs.litellm.ai/docs/ocr
- [web] The poll interval is often not documented; examples wait 2 s. https://docs.reducto.ai/workflows/async-overview.md
- [web] Result order does not always match upload order. https://platform.claude.com/docs/en/api/messages/batches/retrieve.md
- [web] Jobs stay in `running` with no sign of a stall (snippet). https://learn.microsoft.com/en-us/answers/questions/5648454/document-intelligence-prebuilt-read-with-api-versi
- [web] Expired and unknown ids both give 404 in some products, so a client cannot tell them apart. https://developers.llamaindex.ai/llamaparse/general/data_retention/index.md

## Notes for the technical spec

The criteria outrank the Assumptions in the architecture. `context/product/architecture.md` needs these changes (run `/awos:architecture` with them):

- Status values: `queued`, `parsing`, `summarizing`, `done`, `failed`.
- Parser value `gpt5mini`; new variable `OPENAI_API_KEY`.
- New fields `summary_status` and `summary_error`. A summary failure ends with `status done`, not `failed`.
- Summary calls: 4 in total (first call and 3 retries). A summary failure must not start a new message attempt. TODO(discovery): decide what message attempts still apply to.
- `encrypted` and other permanent parse errors must not go through 3 message attempts.
- TTL of about 1 hour on all document and batch keys, not only on the PDF bytes.
- Worker restart: a claim of pending messages only at start with a 60 s minimum idle time does not meet AC-10. TODO(discovery): periodic claim, or a shorter idle time.
- AC-9: check the upload path with 10 concurrent requests (one `uvicorn` process, file bytes in one `MULTI` write).
- AC-8 and AC-15 need the setting `GEMINI_TEST_MODE` with the values `rate_limit` and `bad_page_count`. TODO(discovery): where the fake behavior sits (in the Gemini client wrapper or in a fake endpoint).
- HTTP codes: 415, 413, 400, 404 are new. All addresses reply 503 while Redis is down.
- Upload: per-file checks with a `rejected` list; 10 files per upload at most.
- New error codes `invalid_pdf` and `gemini_unavailable`; new `summary_status` values `pending` and `skipped`.
- `GET /metrics/queue` fields `length` (XLEN) and `pending` (XPENDING count). AC-17 needs `length` to grow by 3 while the worker is stopped.
